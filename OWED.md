# Owed

What a change introduced a new way for, without yet removing the old way. One line each: what is owed, and who owns it.
A pull request that adds a line here is not done until the line is gone.

- Rename `Circle*` types and stored identifiers to Friends and Groups, with a data migration for existing shared brains. Owner: the repo owner.
- `ConnectionStorage.Typed` (src/IntoChat.OS.Kernel) lifts an `Actor.App` caller to the kernel of its brain for every provider call, carried from the old Platform stamp (caller-model collapse, Task 6). Narrow it to an explicit connector module actor, or to the app itself once providers admit it. Owner: the repo owner.
- `neurons_call` cannot address screen and control neurons (`app.uikit`, `control.listBox`, `control.chatThread`): `neurons_list` lists them, but `IScreen` and the control types are not in `CompiledTypes`, so the call answers "not a neuron type of this brain". Commands reach them only through `POST /brains/{id}/act` and `screen_act`; Ino's own `neurons_call` attempts fail the same way. Owner: the repo owner.
- Signals are not in telemetry: no span or log names `StateChanged`, `SelectionChanged` or a run finishing, so a control's state change is visible in Aspire only as the `INeuronHost/Invoke` and `ISynapseHost/Nudge` hops of its trace, and an Ino run only as its `invoke_agent ino` span. Owner: the repo owner.
- The legacy `POST /apps/event` path still carries commands beside `POST /brains/{id}/act`: its callers are `ui/lib/src/nodes/node_context.dart:18`, `ui/lib/src/core/ui_client.dart:954` and `src/IntoChat.OS.Cli/Program.cs:94`, plus every Kit, `IView` and unit app that activates by key. Move Kit, IView and unit apps to model D (screens and controls on `/act`) and remove the route. Owner: the repo owner.
- Key-activated controls without a command still go through `/apps/event`: `nav_item`, `select`, `tabs`, `switch`, `field`, `chart`, `data_table`, `brain_scene` and chat stop (`choice_card`, `empty_state`, and `error_line` now route through `pressCommand` -> `/act` when carrying a command; `Modules.UI` controls bypass `/apps/event` directly over gRPC). Give each remaining one a command on `/act` and drop its key activation. Owner: the repo owner.
- The OS vault duplicates DigitalBrain's: `OsVaultNeuron`, `VaultPort`, `IKeyWrapper` and `SecretSealer` beside `DigitalBrain.Identity.Local`'s `VaultNeuron`, `MasterKeyWrapper` and `LocalSecretSealer`. Merging them migrates the persisted `mydata.state`; plan the dual read first. Owner: the repo owner.
- The OS identity directory duplicates DigitalBrain's: `IdentityDirectoryGrain` and `DirectoryPort` beside `DigitalBrain.Identity.Local`'s `DirectoryNeuron`, with different persisted state. Merge with a state migration. Owner: the repo owner.
- Brain-scoped HTTP routes have two roots: `OsBrainRoutes` with `BrainAccessFilter` (create on first access, `IBrainAccess`) and DigitalBrain's `BrainRouteGroups` (identity@1 membership), which says it replaces the OS one. Decide the behavior, move the callers, delete `OsBrainRoutes`. Owner: the repo owner.
- `OsNeuronSurface` wraps DigitalBrain's `NeuronSurface` with assembly-prefix filtering and search; fold the generic parts into DigitalBrain and delete the wrapper. Owner: the repo owner.
- The OAuth connection login (`OAuthLoginFlow`, `OAuthCallback`, `OAuthTokenExchange`) names the product in copy, a header and configuration keys; parameterize them and move the flow to DigitalBrain. `GuestSurface` moves to the cloud repository with the cloud split. Owner: the repo owner.
- Fifteen modules keep their contracts in a `Contracts` folder inside the implementation assembly (for example `IGmail` in Google), so sandboxed apps cannot reach them; give each module that sandboxed code should reach its own `Contracts` assembly. Owner: the repo owner.
