Two-Plane Architecture: CodeOrchestrationSynapse & Leased Devcontainer Slots

A unified architectural blueprint reconciling two essential, non-competing execution requirements: Plane 1 (Code Mode) via an IAW-inspired CodeOrchestrationSynapse executing typed C# Neuron interactions in the native client/cloud sandbox, and Plane 2 (Dev Mode) via leased Docker Compose devcontainer slots (agent-dev-slots) for full-stack repo engineering and live .NET Aspire verification.

Owner Architectural Direction: Both Planes Are Indispensable

In reviewing the initial RFC, the owner directed that Option A (IntoChat Native Sandbox + Connected Client Nodes) and Option C (Leased Devcontainer Slots via agent-dev-slots + Aspire) are not competing alternatives. They serve two entirely different, complementary planes:

Plane 1 — "Code Mode" (Programmable Neuron & Client Orchestration): When Ino or a user needs to orchestrate multiple cluster Neurons, aggregate data across apps, or automate local client files/tools, an LLM step-by-step tool loop is slow and wasteful. Instead, an agent writes and runs a standalone typed C# script (as pioneered in IAW's CodeOrchestratorAgent.cs) running directly in IntoChat Native Sandbox (on a connected Windows/Linux/Android client or cloud worker) calling cluster Neurons over the closed edge bridge. Orchestrating neurons via compiled C# code is one of IntoChat's most powerful superpowers.

Plane 2 — "Dev Mode" (Full-Stack Repo Engineering & Aspire Self-Improving Loop): When Ino needs to clone a repo, branch worktrees, compile heavy .NET SDK/Flutter solutions, run multi-slice parallel coding (InoNativeHarness), and spin up live candidate Aspire hosts (Postgres, ClickHouse, Redis, Orleans silos), it leases an isolated slot from hanzhad/agent-dev-slots with dynamic port mapping, ephemeral home (no ~/.ssh leaks), and UID 1000 security.

IAW Reference Architecture Direct Orleans Socket

Source: E:\projects\Projects\IAW\src\Agents\Orchestration\CodeOrchestratorAgent.cs

  • Mechanism: LLM generates a standalone C# console project (net11.0) with using var iaw = await IAWCluster.Connect(args); and iaw.Get<T>(taskId).
  • Compilation: Pre-sanitizes usings via CodeValidator, runs dotnet build, feeds compiler diagnostics back to LLM in a 2-attempt repair loop.
  • Execution: Spawns an unconfined child process on the developer machine; writes structured output to result.json.
  • Vulnerability: Connects directly as a member of the Orleans cluster; exposes cluster storage, secrets, and database ports. Cannot run safely on remote client devices or untrusted networks.
IntoChat OS Two-Plane Architecture Closed Edge Proxy + Sandbox

Source: IntoChat.OS.Kernel/Sandbox + #414 Closed Orleans Gateway

  • Mechanism: CodeOrchestrationSynapse generates typed C# script against real contracts (net11.0), resolving proxies via os.Get<T>(key).
  • Edge Crossing: Dispatches calls over /edge/sandbox/invoke using a short-lived, least-privilege AppToken minted by AppTokenService.
  • Sovereign Execution: Runs inside IntoChat Native Sandbox on a Connected Client Node (Windows, Linux, Android) or Cloud Sandbox.
  • Security Boundary: Zero Orleans socket access, zero secrets in environment variables, automatic durable suspension on [PersonOnly] confirmation cards.

Visualizing how Ino routes incoming requests to Plane 1 or Plane 2 — and how the two planes collaborate dynamically.

⚡ How Plane 1 and Plane 2 Collaborate in Practice Real-World Flow

Scenario: The user notices in chat that candidate verification builds fail intermittently on Aspire port allocation.
1. Plane 1 Invocation: Ino triggers a CodeOrchestrationSynapse. In <1 second, a generated C# script calls os.Get<IGitHub>(key) and os.Get<ILoggerStream>(key) over the closed edge bridge, aggregates 50 build logs, discovers the exact port clash, and outputs a formatted table into chat.
2. Handshake to Plane 2: Ino asks: "Would you like me to fix this in ProcessCandidateHost.cs and verify live?" The user approves.
3. Plane 2 Invocation: Ino launches EngineerFlow. It leases a pre-warmed slot from agent-dev-slots, runs InoNativeHarness (implementing the fix via local Ollama coder), boots candidate Aspire on a dynamic leased port, and verifies /health and MCP probes.
4. Completion: Plane 2 opens a clean PR, while Plane 1 posts the interactive ChangeCard with diff and verification metrics back into chat.

🛡 Where Microsoft MXC Fits In Hardening for Plane 1

Microsoft's Microsoft.Mxc.Sdk is not a standalone orchestrator. Instead, it serves as an optional, ultra-fast OS containment engine for Plane 1 on desktop workstations. On Windows and Linux, IntoChat.OS.Sandbox can wrap generated C# scripts in an MXC ProcessContainer to enforce folder read/write boundaries and scrub environment variables without needing Docker.

☁ Where Cloud ACA Dynamic Sessions Fits In Headless Fallback for Plane 2

When the user is away from their workstation and all connected client machines are asleep, Azure Container Apps (ACA) Dynamic Sessions provides an on-demand, scale-to-zero Kata microVM environment. It acts as the cloud runner host for Plane 2's agent-dev-slots, executing background refactoring tournaments without draining user battery.

Section 4

Deep Dive: Should CodeOrchestrator Be a Synapse?

A rigorous architectural answer to the owner's design question: Yes — CodeOrchestrationSynapse (a durable DigitalBrain Synapse/Flow) combined with the ICodeSandbox capability is the exact right design.

✔ The 5 Architectural Pillars of CodeOrchestrationSynapse Architectural Verdict

In IntoChat OS, an ad-hoc agent is merely a prompt loop. A Synapse, by contrast, is a first-class, durable, reactive reactive unit of code governed by DigitalBrain analyzers, capable of holding state, subscribing to signals, and interacting with cluster capabilities. Implementing Code Orchestration as a Synapse provides five critical superpowers:

1. Scoped Grant & AppToken Minting
The Synapse inspects the user intent, queries CodeGraph for only the required [NeuronContract] interfaces (e.g. INotifications, ITables), and mints a short-lived, least-privilege AppToken authorizing only those contracts. The script cannot reach unauthorized Neurons.
2. Roslyn Compile & Repair Loop
Employs an in-memory Roslyn compiler with AST sanitization (stripping reflection, unmanaged calls, or raw sockets) and a deterministic repair loop (feeding compiler diagnostics back to the LLM) before any code ever touches execution.
3. Sovereign Dispatch (Client or Cloud)
Via the ICodeSandbox slot, the Synapse dispatches the compiled script to run where it makes the most sense: on the user's connected desktop PC (to access local files), an Android device, or the cloud IntoChat.OS.Sandbox worker.
4. Durable Suspension on Confirmation Cards
If the orchestrated script invokes a [PersonOnly] or destructive Neuron operation (e.g., deleting a database table or sending an email), the edge bridge returns an approval request. The Synapse durably suspends, displays a Confirmation Card in chat, and resumes cleanly when approved!
5. Crystallization into Permanent Apps-as-Data
When a generated C# script proves useful (e.g. daily PR summary or Linear triage), the user can click "Save as App". IntoChat crystallizes the script into a permanent App-as-Data package with [OnSignal] and [Every] handlers, running in the sandbox forever without re-generation costs.
📄 Code Comparison: IAW Script vs. IntoChat OS Sandboxed Script C# net11.0 Syntax

Notice how IntoChat OS provides identical developer ergonomics to IAW, but executes over the secure IntoChatClient reverse proxy instead of joining the Orleans cluster.

IAW Style (Direct Orleans Cluster) 
// IAW: Direct Orleans Cluster Connect
using Aspire.IAW;
using IAW.Agents.Coding;

using var iaw = await IAWCluster.Connect(args);
var taskId = iaw.TaskId;

// Direct Grain Call (Vulnerable to socket leaks)
var shell = iaw.Get<IShell>(taskId);
var dotnet = iaw.Get<IDotNet>(taskId);

var build = await dotnet.BuildAsync("App.csproj");
File.WriteAllText("result.json", ...);
IntoChat OS Style (Closed Edge Proxy) 
// IntoChat OS: Sovereign Sandboxed Execution
using IntoChat.OS.Client;
using IntoChat.OS.Modules.GitHub.Contracts;
using IntoChat.OS.Modules.Catalog.Contracts;

using var os = await IntoChatClient.ConnectAsync(args);

// Proxied over /edge/sandbox/invoke with AppToken
var github = os.Get<IGitHub>("repo:intochat");
var notify = os.Get<INotifications>();

var prs = await github.ListActivePRsAsync();
await notify.PublishAsync("PRs audited: " + prs.Count);

Phased Rollout Plan & Owner Decisions

Structured vertical slices implementing the Two-Plane Architecture, accompanied by the interactive decision panel for owner sign-off.

Slice RFC-1: CodeOrchestrationSynapse & Scoped AppToken Plane 1 Core

Implement CodeOrchestrationSynapse in src/Modules/Catalog. Implements Roslyn in-memory compilation of generated C# scripts, contract extraction from CodeGraph, least-privilege AppToken minting, and execution in IntoChat.OS.Sandbox.

Slice RFC-2: Connected Client Compute in Devices Plane 1 Sovereign

Extend IntoChat.OS.Modules.Devices to advertise ICodeSandbox capability over the paired P-256 edge relay. Allows CodeOrchestrationSynapse to dispatch scripts to run locally on the user's Windows, Linux, or Android machine.

Slice RFC-3: Leased Devcontainer Slot Provider Plane 2 Core

Implement AgentDevSlotsCandidateHost implementing ICandidateHost for EngineerFlow. Leases Docker Compose slots with dynamic port allocation, unprivileged UID 1000, and ephemeral homes for full Aspire multi-service verification.

Slice RFC-4: Cloud ACA Sessions & Android Edge Worker Plane 2 Cloud

Implement the headless cloud fallback via Azure Container Apps Dynamic Sessions for off-hours Plane 2 runs, plus the Android client background worker for local small-model drafting and test output streaming.
